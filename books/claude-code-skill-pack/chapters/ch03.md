## release-notes — リリースノートを 2 分で作る

### 基本

```bash
# 直近タグからの変更でリリースノートを生成
/release-notes

# 基点タグを指定
/release-notes --since v1.1.0

# 開発者向け (Conventional Changelog 形式)
/release-notes --type dev

# GitHub Release を作らずプレビュー
/release-notes --dry-run
```

### 出力形式

ユーザー向けと開発者向けの 2 種類が生成されます:

**ユーザー向け (`--type user`、デフォルト — GitHub Release ドラフトとして公開):**
```markdown
## v1.2.0 (2026-04-22)

### 新機能
- ダークモード対応を追加
- CSV エクスポート機能を追加

### バグ修正
- ログインセッションが 24 時間で切れる問題を修正
```

**開発者向け (`--type dev` — Conventional Changelog 形式):**
```markdown
## v1.2.0

### Breaking Changes
- `UserConfig` 型から `deprecated` フィールドを削除

### Internal
- Supabase client を v2.42 にアップグレード
```

## issue-triage — バックログを 5 分で整理する

### 基本

```bash
# 全 open issue を優先度スコアリング
/issue-triage

# ラベルでフィルタ
/issue-triage --label bug

# スコア上位 10 件だけ表示
/issue-triage --top 10
```

### スコアリング式

```
Score = Impact × (6 - Effort) + Urgency

Impact  : 1 (軽微) 〜 5 (致命的)
Effort  : 1 (数時間) 〜 5 (数週間)
Urgency : 0 〜 +7 ボーナス (古さ+コメント / milestone / 👍≥5 / urgent ラベル)
```

### 出力例

```
Issue #142: ログインページが Safari で崩れる
  Impact: 4 | Effort: 2 | Urgency: +2
  Score: 4×(6−2)+2 = 18 ← 最優先 (🔴 Sprint必須)
  Labels: bug, frontend

Issue #98: パフォーマンス最適化
  Impact: 3 | Effort: 4 | Urgency: 0
  Score: 3×(6−4)+0 = 6 (🟢 Backlog)
  Labels: enhancement
```

`/issue-triage` は結果を `TRIAGE.md` に保存します。スプリント計画のインプットとして使えます。

## repo-tour — 初見リポジトリを 2 分で把握する

### 基本

```bash
# カレントリポジトリを解析 (REPO_TOUR.md を生成)
/repo-tour

# ファイルに書かず標準出力に表示
/repo-tour --output stdout

# 解析する階層を制限
/repo-tour --depth 2
```

### 生成される内容

```markdown
# Repository Tour: my-project

## 概要
Node.js + TypeScript の REST API。Supabase でデータ永続化。

## ディレクトリ構造 (主要)
src/
  api/       # Express ルートハンドラ
  services/  # ビジネスロジック
  models/    # Supabase スキーマ型定義

## データフロー
Request → Express Router → Service Layer → Supabase

## 開発を始めるには
1. npm install
2. cp .env.example .env (Supabase URL/KEY を設定)
3. npm run dev
```

Mermaid 図も生成されるので、ドキュメントサイトにそのまま貼れます。

## 4 スキルを組み合わせた週次ワークフロー

| タイミング | スキル | 所要時間 |
|---|---|---|
| PR レビューコメント受信後 | `/pr-respond` | 3 分 |
| リリース作業時 | `/release-notes` | 2 分 |
| 週次スプリント計画前 | `/issue-triage` | 5 分 |
| 新規リポジトリ参画時 | `/repo-tour` | 2 分 |

週あたり合計 3〜4 時間の節約。月換算で 12〜16 時間です。
